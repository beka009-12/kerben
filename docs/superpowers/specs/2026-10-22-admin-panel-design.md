# Админка Kerben Travel внутри сайта — дизайн

Дата: 2026-10-22. Статус: дизайн утверждён в чате, спецификация на проверке.

## Зачем

Backend Kerben Travel (FastAPI, `https://13.53.40.37`) уже имеет свою админку (SQLAdmin, `/admin/`), но она
отдельная и неудобная. Нужна одна система: админ управляет данными прямо на сайте Kerben Travel, в его стиле.
Про админку никто не должен знать — на сайте нет ни ссылок, ни признаков её существования.

Заодно в этой же работе:
- «ИИ-гид» везде переименовывается в «ИИ-ассистент» (4 языка, все падежи);
- разделы backend перестают «пропадать» после временного сбоя backend (см. «Кеш при сбое backend»).

## Что сказал заказчик и что допущено

Сказано:
1. Вход — в форме регистрации ИИ-ассистента: email и пароль админа, имя и телефон пустые → страница админа.
2. Шапка сайта на странице админа остаётся; дизайн — аккуратнее SQLAdmin; управление данными в виде таблиц.
3. Аккаунт админа никто не знает.
4. «ИИ-гид» → «ИИ-ассистент».

Допущено (подтверждено заказчиком):
- неудачный вход админа ничем не отличается от обычной ошибки формы;
- токен — только в httpOnly-cookie, все запросы к backend — с сервера Next.js;
- после сохранения сайт сразу показывает изменения;
- интерфейс админки только на русском (тексты backend переводит сам);
- пароль админа вводит сам заказчик, не ИИ.

## API backend, на который опираемся

Из `https://13.53.40.37/openapi.json`:

| Что | Запрос |
| --- | --- |
| Вход | `POST /admin/login/` `{ username, password }` → `{ access_token, token_type }` (OAuth2 Bearer) |
| Кто вошёл | `GET /admin/me/` → `{ id, username, is_active, created_at }` |
| Заявки | `GET /admin/requests/`, `GET /admin/requests/{id}/`, `PATCH /admin/requests/{id}/status/` `{ status }` |
| Разделы | `GET` список и `GET /{id}/` — открыты; `POST`, `PUT /{id}/`, `DELETE /{id}/` — с токеном |
| Перевод тура | `POST /tours/{id}/translate/` — перевести заново |

Статусы заявки: `new`, `in_progress`, `completed`, `cancelled`.
Единицы цены: `per_person`, `per_day`, `per_night`, `per_hour`, `per_trip`.
Тип тура: `classic`, `adventure`, `cultural`, `winter`, `individual`, `combined`.
Фото везде — строка-ссылка; загрузки файлов в API нет.

Особенности, которые учитываем:
- `email` из формы уходит в backend как `username`.
- Список вертолётных туров не отдаёт `price_unit`, `instruction`, `included`, `is_active`. Поэтому `PUT`
  отправляет **только изменённые поля** — иначе сохранение затрёт то, чего форма не знает.
- Публичные списки могут не показывать скрытые записи (`is_active=false`). Админка запрашивает списки
  с токеном; если backend и так прячет скрытые — это ограничение backend, проверяем после первого входа.
- Брони конкретных туров (`POST /bookings/`) в API не читаются — в админке только заявки `/admin/requests/`.

## Подход

Выбран **один общий конструктор по описанию разделов**. Для каждого раздела в коде одно описание:
адрес в API, поля (подпись, тип, обязательность, связь), колонки таблицы, дочерние разделы (фото, программа),
какие кеши сайта сбросить после изменения. По нему строятся таблица и панель редактирования.

Отклонены: генерация форм из `openapi.json` на лету (английские имена полей, ломается от изменений backend)
и отдельная страница на каждый раздел (~20 почти одинаковых страниц).

## Вход и сессия

- `AuthForm` в режиме регистрации: если **имя и телефон пустые**, а email и пароль заполнены — сначала
  вызывается серверное действие `adminSignIn(email, password)`.
  - Успех → cookie `kg_admin` (httpOnly, `secure` в production, `sameSite=lax`, `path=/`, 8 часов) и переход
    на `/{lang}/admin`.
  - Неудача (неверные данные, backend недоступен) → форма продолжает как обычно: показывает «введите имя» и
    «введите телефон». Ответ действия — только `{ ok: boolean }`, без причин.
- В режиме «Войти» и при заполненных имени/телефоне поведение формы не меняется: пароли обычных
  пользователей в backend админки не уходят.
- `requireAdmin()` (server-only): читает cookie, проверяет токен через `GET /admin/me/`. Нет cookie или
  backend ответил 401 → `notFound()` (страница «не найдена», как любой несуществующий адрес).
- Выход — действие `adminSignOut()`: удаляет cookie и ведёт на главную.
- Ограничение частоты попыток не добавляем: `/admin/login/` backend и так открыт напрямую, защита — на его стороне.

## Страницы

Все под `src/app/[lang]/admin/` (язык в адресе любой, интерфейс русский). Чтение cookie — внутри `<Suspense>`,
как требует Cache Components (верхний уровень layout cookie не читает).

- **Оболочка.** Шапка сайта остаётся; подвал и нижнее мобильное меню на `/admin` скрыты (`ChromeGate`).
  Слева — меню разделов с группами («Каталог», «Справочники», «Контент»), сверху меню — имя админа и «Выйти».
  На узком экране меню — выпадающий список разделов над контентом.
- **Обзор** `/admin`: карточки — новые заявки, число записей по разделам; последние 5 заявок.
- **Заявки** `/admin/requests`: вкладки по статусам со счётчиками; строка — имя, телефон (`tel:` и WhatsApp),
  направление, дата, сколько человек, когда пришла; статус меняется выпадающим списком в строке;
  по нажатию — панель с полным сообщением.
- **Раздел** `/admin/[resource]`: таблица (миниатюра, главные колонки, «Активен/Скрыт»), поиск по тексту,
  «Добавить». Нажатие на строку — боковая панель редактирования (на телефоне — на весь экран):
  - поля по типам: текст, многострочный текст, число, цена + единица, выбор из списка, связь с другим
    разделом (выпадающий список названий), да/нет, ссылка на фото с превью, список удобств отеля;
  - у туров, отелей, транспорта, вертолётов, трекинга — вкладки «Основное», «Фото» (ссылки, порядок,
    превью, добавить/удалить), у туров и трекинга ещё «Программа по дням»;
  - у тура — кнопка «Перевести заново»;
  - удаление — с подтверждением в диалоге.
- Неизвестный `[resource]` → `notFound()`.

## Данные, кеш, ошибки

- Чтение в админке — серверные компоненты, без кеша, с токеном; язык `ru`.
- Запись — серверные действия (`saveRecord`, `deleteRecord`, `setRequestStatus`, `retranslateTour`).
  Каждое заново проверяет cookie (серверные действия — публичные адреса), проверяет поля по описанию
  раздела и шлёт в backend с `Authorization: Bearer`.
- После успеха — `updateTag` для кешей сайта, которые затронуты: `tours`, `catalog`, `about`, `contacts`.
  Посетители видят изменения со следующего запроса.
- Ошибки:
  - 401 → cookie удаляется, панель показывает «Сессия истекла» со ссылкой на вход в ИИ-ассистенте;
  - 422 → `detail[].loc` из FastAPI превращается в ошибки у нужных полей;
  - сеть/таймаут/5xx → уведомление «Бэкенд не отвечает. Попробуйте ещё раз»; введённые данные не теряются.
- Уведомления об успехе — короткий тост «Сохранено», «Удалено».

## Скрытность

- Ни одной ссылки на `/admin` на сайте.
- Без входа `/admin/*` — обычная 404.
- `robots.ts`: `disallow /*/admin`; у страниц админки `robots: { index: false, follow: false }`; в sitemap не попадают.

## Кеш при сбое backend

Сейчас `loadList` (и такие же функции в `tours.ts`, `about.ts`, `contacts.ts`) ловит ошибку **внутри**
`"use cache"` и кеширует пустой список — после сбоя раздел остаётся пустым, пока кеш не обновится.
Пропажу машин и вертолётов повторить не удалось (сейчас backend отдаёт по 20 записей), но это самая
вероятная причина. Исправление: при ошибке кешируемая функция бросает исключение (неудача не кешируется),
пустой список подставляется снаружи.

## Переименование

`ИИ-гид` → `ИИ-ассистент` во всех формах (`ИИ-гида` → `ИИ-ассистента`, `ИИ-гиду` → `ИИ-ассистенту`,
`ИИ-гидом` → `ИИ-ассистентом`) в `ru.json`; `AI guide` → `AI assistant` в `en.json`; немецкий и китайский —
по смыслу («KI-Assistent», «AI 助手»). Комментарии в коде — по ходу, если файл и так меняется.

## Где код

- `src/lib/admin/resources.ts` — описания разделов (общие для сервера и браузера).
- `src/lib/admin/form.ts` — чистые функции: значения формы ↔ запись backend, только изменённые поля,
  разбор ошибок 422.
- `src/lib/admin/session.ts` (server-only) — cookie, `requireAdmin()`.
- `src/lib/admin/api.ts` (server-only) — запросы к backend с токеном.
- `src/app/[lang]/admin/actions.ts` — серверные действия.
- `src/app/[lang]/admin/` — `layout.tsx`, `page.tsx`, `requests/page.tsx`, `[resource]/page.tsx`.
- `src/components/admin/*` — оболочка с меню, таблица, панель редактирования, поля, заявки, диалог, тосты.
  Правила CSS проекта: свой файл на компонент, одиночные классы, переменные из `globals.css`.

## Проверка

- Vitest:
  - `form.ts`: перевод типов, только изменённые поля, разбор 422;
  - `resources.ts`: у каждого раздела есть все обязательные поля backend;
  - `adminSignIn`: успех ставит cookie, неудача — `{ ok: false }` без cookie (fetch подменён);
  - `AuthForm`: вход админа пробуется только при пустых имени и телефоне;
  - кеш: при ошибке backend функция бросает, а не возвращает пустой список.
- `npm run check` (lint, типы, тесты, сборка).
- В браузере: без входа `/ru/admin` → 404; вход заказчик выполняет сам во встроенном браузере, затем
  проверяются все разделы, добавление/изменение/удаление на тестовой записи, смена статуса заявки,
  обновление сайта после сохранения, вид на телефоне.

## Вне рамок

- Загрузка файлов фото (нет в API).
- Управление учётными записями админов.
- Чтение броней `/bookings/` (нет в API).
